# 来源与条件页面集成说明

## 范围

张锦昊负责的来源与条件模块位于 `frontend/src/modules/sources/`。页面支持读取公开 HTML 通知，以及查看当前事项已关联的来源、快照和候选要求；支持来源切换、历史版本切换、原文展开及出处查看。来源生命周期、程序检查状态和要求提取状态分别显示。

运行范围为当前登录账户的个人工作区，依据 `docs/development/core-flow-contract.md`。页面展示通知中的要求及提取状态；接口返回 `self_check` 时，逐条展示四态自查结论、原因、缺失信息和缺口出处。页面提供公开来源分析、当前事项排名补录与保存，以及保存核对后的重新自查入口。

## 技术栈与启动

Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、Axios、Zod；使用 npm 和随附锁文件管理依赖。

需要 Node.js 24 LTS 及 npm。在 `frontend/` 中执行：

```sh
npm ci
npm run dev
```

访问 `http://127.0.0.1:5173/matters`，从事项列表进入工作区，再打开“来源与条件”。也可直接访问 `/matters/{matter_id}/sources`。应用沿用陈常群 PR #43 的布局、导航及事项读取入口；事项未读取成功时不挂载业务页面。

默认配置保持服务未接通状态。真实联调在 `.env.local` 中设置 `VITE_LOCAL_DEMO_MATTERS=1` 和 `API_PROXY_TARGET=http://127.0.0.1:8000`，然后重启开发服务。事项、来源、计划共用 `src/shared/http.ts` 的 Axios 客户端，请求前缀为 `/api/v1`；需要改变前缀时设置 `VITE_API_BASE_URL`。环境变量中不得填写密钥；所有 `VITE_` 变量会进入浏览器产物。

生产部署需托管 `frontend/dist`，为前端路由配置 HTML 回退，并为 `/api` 配置真实后端反向代理。`vite preview` 仅预览构建产物，不提供开发代理。

## 读取契约

接口沿用当前主分支的事项业务协议，自查字段遵循 `docs/backend/requirement-self-check.md`。后端提供自查保存、按事项读取、来源即时关联、事项级个人事实和模型传输统一授权，联调需将独立测试库迁移至 0018 并使用有效登录会话。

| 请求                                            | 用途                         | 响应                                                                                     |
| :---------------------------------------------- | :--------------------------- | :--------------------------------------------------------------------------------------- |
| 工作区传入 `matterId`、`matter`                 | 已读取的事项标题、年度和范围 | 工作区负责读取及归属校验                                                                 |
| `GET /api/v1/matters/{matter_id}/sources`       | 来源与要求证据链             | `{ sources: [{ ..., snapshots: [{ ..., requirements: [{ ..., evidence: [...] }] }] }] }` |
| `POST /api/v1/matters/{matter_id}/sources/read` | 读取并登记公开 HTML 通知     | 请求为链接、发布单位、事项年度和可选范围；返回来源、快照及创建标记                       |

来源读取成功即与当前事项关联，未生成要求或候选时也应在来源列表返回。要求从每个快照的 `requirements` 读取，没有另行调用条件列表接口。

公开来源读取成功后，在“本次来源读取结果”展示服务端返回的标题、发布单位、范围、获取时间、正文和定位片段，并重读关联来源列表。本次读取结果卡片仅在当前页保留；刷新后通过事项来源列表重读同一来源与快照。来源读取结果不代表要求已生成或自查已完成。

关联列表尚未返回本快照的要求时，读取结果显示“已读取，待分析”；已有要求的同一快照显示“已读取通知”。已关联但无要求的快照，在要求区同样显示“已读取，待分析”。此提示说明尚无可展示的要求，不代表 Agent 已进入运行队列。

`contracts.ts` 校验响应必需字段及事项、快照关联；未知状态显示原始编码并标为待识别。只有有效 HTTP(S) 原文链接可打开，引用文本由 Vue 文本绑定显示。日期字段保留日期精度，带时区的时间转为北京时间。

每条要求可包含 `self_check`，其结构遵循后端自查保存协议。`conclusion` 的 `matched`、`not_matched`、`missing_info`、`needs_user_review` 分别显示“按现有信息符合”“按现有信息不符合”“待补充信息”“待用户核对”；同时展示 `reason`、`missing_fields`、`computed_deadline_at` 和 `gaps`。缺口关联的来源及快照已在本列表返回时，提供切换查看入口。字段缺失或为 `null` 时明确提示尚无可读取的个人自查结果；不从 `extract_status` 推断资格结论。未识别的结论编码保持中性提示。

## 当前事项排名补录

页面依据 [Beta Page 3](https://www.figma.com/design/feczCbKUHrybftac7eB7qW/OfferPilot?node-id=16-758) 组织来源和辅助自查。首屏显示所选快照、个人排名保存状态及“补充排名信息”入口；展开表单时保持已加载的数据和未保存输入。数字合法时显示比例预览，本人勾选确认后才可提交保存。来源原文、历史快照和逐条依据可展开查看。窄屏先显示自查，再显示来源文件；排名字段和操作按钮按单列排列。页面示例：[390px 自查与历史快照](images/source-conditions-mobile.png)、[390px 排名表单](images/ranking-supplement-mobile.png)。

`RankingSupplement.vue` 提供本人排名、同一统计范围的参与排名总人数，以及本人真实性确认。缺项时列明待补充内容；两项数字必须为安全范围内的正整数，排名不能超过总人数。修改数字后需重新勾选本人确认。通过本地检查后展示排名除以总人数的比例，不据此产生个人资格结论。

未保存输入仅保存在当前组件内存中，切换事项清除，离开页面或刷新前提示；读取来源失败不清空排名输入。已保存排名从后端恢复，页面不把个人事实写入浏览器持久存储，不跨事项复用，不标注为官方核实。

`rankingApi.ts` 调用 `GET/PUT /api/v1/matters/{matter_id}/facts/gpa.rank`。读取当前记录及历史，并校验全部记录的 `matter_id`。首次读取失败时允许重试，保存保持禁用；本地检查成功只说明输入合法。保存前重读当前版本，发生其他页面修改时保留输入并要求重新核对。保存请求携带名次、总人数以及已读取记录的 `scope/valid_from`，保留已有属性。

收到有效保存响应后重读，核对事实 ID、事项、版本和内容指纹，再发起重新自查。保存失败保留输入；超时、服务异常或无法核验响应时提示结果未知，要求先重读，不自动重复保存。保存已确认但后续读取或自查失败时分别说明状态，允许重读后仅重新自查。保存或重新自查均不创建正式任务，任务创建沿用显式确认入口。

`rankingFacts.ts` 提供排名值、事实版本及受影响候选的结构校验。名次使用 `value.position`、总人数使用 `value.cohort_size`；`percentile` 使用 0–100 百分数。只保存百分位的既有记录保留空名次及人数，不反推输入。读取无当前值时接受 `fact: null`，保存成功须与提交的名次、人数及属性一致。

本轮采用当前用户、当前事项隔离的个人事实，不跨事项复用。后端保存、读取、Agent 取值和候选依据版本均校验当前事项；修改当前事项的排名只影响该事项的候选。`scope` 仅描述统计范围。前端同时校验保存结果的 `affected_plans` 全部属于当前事项，只提示受影响数量，不直接将候选标记为过期。

## 开始分析与运行反馈

`modules/analysis/AgentAnalysis.vue` 接收当前事项及要分析的来源。最近读取成功的来源可直接分析。选择关联来源或查看引用快照时，分析对象随所选来源切换。入口会重新读取该公开网页。运行返回“等待确认”及已入库的候选 ID 时，“审阅本次候选计划”打开该版本。

| 请求                                          | 约定                                                                                                                                           |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/v1/matters/{matter_id}/agent-runs` | 发送一个已核验的来源 URL、发布单位、同事项年度、可选来源范围和独立 UUID `operation_id`；不提交未保存排名或授权标识，后端查询当前用户的统一同意 |
| `GET /api/v1/agent-runs/{run_id}`             | 读取持久化运行状态；返回标识须与请求一致                                                                                                       |

POST 默认最多等待 420 秒，覆盖后端连续抽取、规划调用及来源读取、持久化的总耗时，期间禁止重复点击。可通过 `VITE_AGENT_RUN_TIMEOUT_SECONDS` 配置正整数秒数，部署时应与实际后端总时限及代理时限对齐；修改后重启开发服务或重新构建。`200` 响应仍按 `run.status` 判断：失败和等待用户分别显示原因及缺项；等待确认须返回已保存候选 ID。分析入口返回正式任务写入状态时停止成功提示，要求核对已保存结果。前端等待超时单独提示后端可能仍在运行，允许刷新已保存的来源与候选，不自动重发，也不把前端超时归为模型失败。

当前标签页按事项保存操作 UUID、来源 ID、运行 ID 和最近运行状态，不保存排名、个人事实或原文。刷新后可查询已知运行；服务重启后未完成的运行返回“已中断”，明确提示原运行不会继续，并允许重新发起。`404 agent_run_not_found` 单独提示运行不可查询。来源、自查与候选始终从各自的持久化读取接口恢复，运行 ID 不作为业务结果恢复的前提。

超时、网络错误或无法校验的响应保持结果未知；先提供刷新已保存结果及查看候选入口。用户主动再次发起前需确认原请求可能仍在执行，新请求采用新的操作 UUID；不自动重试。离开页面取消浏览器等待，不表示后台运行已停止。服务端返回授权、来源或模型错误时展示失败反馈，不自行绕过授权检查。

补录后的重新自查沿用 Agent 运行入口，使用新的 `operation_id`，由后端读取当前事项的已确认事实，前端不传 `confirmed_facts`。手动分析按钮在排名保存期间禁用；保存或读取核对完成后，通过 `startAfterRanking` 衔接自查，该入口不依赖父组件传播的保存中标志，仍核对运行状态、会话存储、事项、来源、年度和统一授权。若所选来源已变化则保留保存结果并提示未取得重新自查结果。无来源或暂不能分析时仍可保存排名，随后使用“仅重新自查”。运行返回的四态、原因和原文依据由持久化来源接口重读，页面不从本地比例生成资格结论。

自查进入页面、组件及运行入口时，明确的未发起原因逐级返回到排名反馈区：来源未选或变化、组件尚未就绪、授权读取失败、当前运行不允许重发、会话存储不可用及用户取消重发确认。已确认保存的排名保持有效，可在条件满足后仅重新自查。仅已建立的新请求遇到网络或响应问题时显示结果尚未确认。

## 模型传输同意

授权接口遵循 `docs/backend/model-transfer-consent.md`，归属于当前用户，统一覆盖其全部事项。个人排名事实仍按事项保存和读取。

| 请求                                                 | 用途                               |
| :--------------------------------------------------- | :--------------------------------- |
| `GET /api/v1/model-transfer-consent`                 | 读取 `disclosure` 和当前 `consent` |
| `POST /api/v1/model-transfer-consent`                | 用户主动确认后授予，请求体为空     |
| `DELETE /api/v1/model-transfer-consent/{consent_id}` | 撤回当前用户的指定同意             |

进入来源页先 GET，展示服务端披露的服务商、可空模型名称、用途、发送字段、`consent_scope` 和数据处理说明。无当前同意时，由用户主动勾选并点击授予后才 POST；页面明确说明覆盖全部事项及后续更换的外部模型服务。授予前重读披露，内容变化时要求重新阅读并确认；授予后再次 GET，校验标识、有效状态、用途及字段类别。授权不绑定服务商或模型，已有有效同意在模型服务更换后继续使用。

每次开始分析或重新自查前再次 GET。运行请求只发送分析字段，不携带 `model_transfer_consent_id`，服务端按当前用户自动核对统一授权。未授予时，页面提供先授权再发起分析的入口；排名可以先保存。服务端明确返回 `422 model_transfer_consent_required` 时记录为“未发起”，允许核对授权后重试；超时和服务异常仍保持结果未知。

用户撤回时立即停用本页授权状态，DELETE 后再 GET 核对。撤回失败或结果未知时不自动恢复该记录，允许重新读取和重试撤回；后端仍返回待撤回记录时继续阻止新分析。撤回统一影响全部事项的后续调用检查；已经发出的外部请求按服务端披露说明处理。切换事项后重新读取同一用户的统一同意，晚到响应不会覆盖当前页面；撤回结果不确定时的阻塞在事项切换后继续保留。授权记录不写入浏览器持久存储。本版本不提供到期时间、用途分拆、授权历史列表或第三方条款绑定。

## 页面状态与协作边界

首次读取显示加载态；读取失败提供重试；空列表说明关联条件。网络中断、超时或服务临时不可用时，刷新保留上次资料并标明读取时间；身份、权限、事项不存在或响应校验未通过时清除已展示资料。切换事项立即清除旧事项数据并取消未完成请求，旧请求返回不会覆盖当前事项。

`SourceConditionsPage.vue` 已通过 `workspaceIntegrations.modules.sources` 注册到 `/matters/:matterId/sources`，接收 `matterId`、只读的 `matter`，共用应用 Pinia、Vue Router 和 Element Plus。来源登记成功后发送 `changed`，工作区重新读取事项。要求列表接收快照与可用出处集合，通过事件请求切换出处。业务样式限定在 `.business-module` 内，沿用工作区的品牌色、字体及卡片样式。

联调需要后端业务服务、0018 数据库迁移、有效登录会话和真实事项数据。公开来源分析、状态查询、排名保存与读取、模型传输同意及保存后重新自查已接入约定接口，完整业务链路需要 QA 使用同一后端版本及前端最新提交在独立测试库中验收。

## QA 入口与定位约定

真实测试服务接入方式见[前端开发与联调指南](development.md)。来源页入口为 `/matters/{matter_id}/sources`，候选页为 `/matters/{matter_id}/plan`；从真实创建接口返回的事项 ID 进入。现有 `npm run test:matters:live` 仅检查事项创建、列表、详情和刷新，来源及候选完整链路仍需独立执行。

| 目标           | 定位方式                                                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 来源页及刷新   | `getByTestId('sources-page')`、`getByTestId('sources-refresh')`                                                                                      |
| 读取表单       | `getByTestId('source-import')`，输入项 `#source-url`、`#source-publisher`、`#source-scope`                                                           |
| 读取操作及结果 | `getByTestId('source-read-submit')`、`getByTestId('source-read-result')`                                                                             |
| 来源及版本     | `getByTestId('source-card')` 按 `data-source-id` 区分；`#snapshot-version` 切换版本                                                                  |
| 要求及自查     | `getByTestId('requirements')` 的 `data-snapshot-id`；`requirement-card` 的 `data-requirement-id`；`self-check` 的 `data-conclusion`                  |
| 排名输入       | `#ranking-rankPosition`、`#ranking-totalStudents`、`#ranking-confirmed`                                                                              |
| 排名读取与保存 | `ranking-panel`、`ranking-refresh`、`ranking-save`、`ranking-recheck`、`ranking-error`、`ranking-notice`；`ranking-saved` 提供事实 ID、版本及事项 ID |

验收时先读取真实来源，核对返回的来源及快照 ID；未生成要求时检查“已读取，待分析”。要求与自查结果保存后，刷新及重新进入事项，按相同 ID 对照四态、原因、缺失信息、缺口和原文出处。重启后端后重复读取，确认结果来自持久化数据。这些恢复接口已有实现，实际通过与否以同一后端提交及迁移后的测试库验收结果为准。

分析入口与状态查询分别使用 `analysis-start`、`analysis-status-refresh`；已保存结果重读使用 `analysis-results-refresh`。反馈区 `analysis-result` 包含 `data-run-id`、`data-run-status` 和 `data-source-id`，错误区为 `analysis-error`。未完成运行的验收应在发起后刷新或重启服务，查询已知运行，核对“已中断”或找不到时的明确提示及重新发起操作；不恢复原运行。真实中断及重新发起仍待可用后端联调。

排名验收先点击 `ranking-open` 展开 `ranking-disclosure`，再填写表单。排名验收覆盖：缺少排名时显示待补充；非法名次不发送 PUT；保存后刷新及重启读回相同事项的事实；保存失败保留输入；保存成功后重新自查返回符合或不符合及原因、依据；修改事实后旧候选不能继续确认；仅自查与拒绝均不创建任务；切换事项不会显示另一事项的排名；保存结果未知时先重读核对。完整流程以 QA 对最新 PR head 的实际结果为准。

授权定位：`analysis-consent`、`consent-refresh`、`consent-disclosure`、`#consent-confirmed`、`consent-grant`、`consent-revoke`、`consent-error`、`consent-notice`。`consent-active` 提供 `data-consent-id`。验收覆盖未同意时无 POST/运行、披露更新后重新确认、同意授予后重读、运行请求不携带授权标识且后端核对统一授权、刷新恢复、撤回重读、跨事项共用同意、撤回后全局阻止、授权请求失败及仅重新自查。实际模型返回新结论和旧候选拦截仍须在真实模型配置可用时联调。

## 检查命令

```sh
npm run lint
npm run format:check
npm run test:unit
npm run build
```

单元检查覆盖外链安全、事项标识输入、未知机器状态、时间精度、自查四态展示、缺失结果、自查字段校验、排名非法输入和比例边界。真实来源展示、版本切换、自查结果读取与刷新、事项隔离需在真实后端与数据库启动后联调验收。
