# 来源与条件页面集成说明

## 范围

张锦昊负责的来源与条件模块位于 `frontend/src/modules/sources/`。页面支持读取公开 HTML 通知，以及查看当前事项已关联的来源、快照和候选要求；支持来源切换、历史版本切换、原文展开及出处查看。来源生命周期、程序检查状态和要求提取状态分别显示。

运行范围为单用户本地演示，依据 `docs/development/alpha-scope-contract.md`。页面展示通知中的要求及提取状态；接口返回 `self_check` 时，逐条展示四态自查结论、原因、缺失信息和缺口出处。页面提供公开来源分析入口，以及当前事项的排名补录输入和本地校验；排名保存和补录后的重新自查仍需接口接齐。

## 技术栈与启动

Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、Axios、Zod；使用 npm 和随附锁文件管理依赖。

需要 Node.js 24 LTS 及 npm。在 `frontend/` 中执行：

```sh
npm ci
npm run dev
```

访问 `http://127.0.0.1:5173/matters`，从事项列表进入工作区，再打开“来源与条件”。也可直接访问 `/matters/{matter_id}/sources`。应用沿用陈常群 PR #43 的布局、导航及事项读取入口；事项未读取成功时不挂载业务页面。

默认配置保持服务未接通状态。真实联调在 `.env.local` 中设置 `VITE_LOCAL_DEMO_MATTERS=1` 和 `API_PROXY_TARGET=http://127.0.0.1:8000`，然后重启开发服务。事项、来源、计划共用 `src/shared/http.ts` 的 Axios 客户端，请求前缀为 `/api/v1`；需要改变前缀时设置 `VITE_API_BASE_URL`。环境变量中不得填写密钥；所有 `VITE_` 变量会进入浏览器产物。

生产部署需托管 `frontend/dist`，为前端路由配置 HTML 回退，并为 `/api` 配置真实后端反向代理。`vite preview` 仅预览构建产物，不提供开发代理。

## 读取契约

当前适配李义东的业务接口 PR #41。自查展示字段依据提交 `36afb05441f63dcbd8f4a5b3096cc27cc1d211fd` 的 `docs/backend/requirement-self-check.md`。该接口实现尚待合并；自查字段的业务接收、保存和读取仍需后端接齐，主分支没有这些路由时会出现接口读取失败提示。

| 请求                                            | 用途                         | 响应                                                                                     |
| :---------------------------------------------- | :--------------------------- | :--------------------------------------------------------------------------------------- |
| 工作区传入 `matterId`、`matter`                 | 已读取的事项标题、年度和范围 | 工作区负责读取及归属校验                                                                 |
| `GET /api/v1/matters/{matter_id}/sources`       | 来源与要求证据链             | `{ sources: [{ ..., snapshots: [{ ..., requirements: [{ ..., evidence: [...] }] }] }] }` |
| `POST /api/v1/matters/{matter_id}/sources/read` | 读取并登记公开 HTML 通知     | 请求为链接、发布单位、事项年度和可选范围；返回来源、快照及创建标记                       |

来源列表仅包含已通过要求或候选项与当前事项关联的来源。列表为空不代表登记接口没有保存来源。要求从每个快照的 `requirements` 读取，没有另行调用条件列表接口。

公开来源读取成功后，在“本次来源读取结果”展示服务端返回的标题、发布单位、范围、获取时间、正文和定位片段，并重读关联来源列表。该次结果只在当前页面保留；刷新恢复尚未关联的来源需要后端提供相应事项关联能力。来源读取结果不代表要求已生成或自查已完成。

关联列表尚未返回本快照的要求时，读取结果显示“已读取，待分析”；已有要求的同一快照显示“已读取通知”。已关联但无要求的快照，在要求区同样显示“已读取，待分析”。此提示说明尚无可展示的要求，不代表 Agent 已进入运行队列。

`contracts.ts` 校验响应必需字段及事项、快照关联；未知状态显示原始编码并标为待识别。只有有效 HTTP(S) 原文链接可打开，引用文本由 Vue 文本绑定显示。日期字段保留日期精度，带时区的时间转为北京时间。

每条要求可包含 `self_check`，其结构遵循后端自查保存协议。`conclusion` 的 `matched`、`not_matched`、`missing_info`、`needs_user_review` 分别显示“按现有信息符合”“按现有信息不符合”“待补充信息”“待用户核对”；同时展示 `reason`、`missing_fields`、`computed_deadline_at` 和 `gaps`。缺口关联的来源及快照已在本列表返回时，提供切换查看入口。字段缺失或为 `null` 时明确提示尚无可读取的个人自查结果；不从 `extract_status` 推断资格结论。未识别的结论编码保持中性提示。

## 当前事项排名补录

`RankingSupplement.vue` 提供本人排名、同一统计范围的参与排名总人数，以及本人真实性确认。缺项时列明待补充内容；两项数字必须为安全范围内的正整数，排名不能超过总人数。修改数字后需重新勾选本人确认。通过本地检查后展示排名除以总人数的比例，不据此产生个人资格结论。

输入仅保存在当前组件内存中，切换事项清除，离开页面或刷新前提示尚未保存；读取来源失败不清空排名输入。页面不写入浏览器持久存储，不跨事项复用，不标注为官方核实。

保存和重新自查服务接通前，操作按钮明确禁用并标明未接通，本地检查成功仍显示“未保存”。接入时需由后端提供当前用户、当前事项的保存与读取、版本变更及旧候选失效机制，由 Agent 返回重新自查的结论、原因和原文依据。保存或重新自查均不创建正式任务，任务创建沿用显式确认入口。

## 开始分析与运行反馈

`modules/analysis/AgentAnalysis.vue` 接收当前事项及要分析的来源。最近读取成功的来源可直接分析，关联来源卡片可切换分析对象。入口会重新读取公开网页，不对历史快照执行离线分析。

| 请求                                          | 约定                                                                                                                         |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/v1/matters/{matter_id}/agent-runs` | 发送一个已核验的来源 URL、发布单位、同事项年度、可选来源范围和独立 UUID `operation_id`；不提交未保存排名或自行构造的授权标识 |
| `GET /api/v1/agent-runs/{run_id}`             | 读取当前进程中的运行状态；返回标识须与请求一致                                                                               |

POST 最多等待 120 秒，期间禁止重复点击。`200` 响应仍按 `run.status` 判断：失败和等待用户分别显示原因及缺项；等待确认须返回已保存候选 ID。分析入口返回正式任务写入状态时停止成功提示，要求核对已保存结果。

当前标签页按事项保存操作 UUID、来源 ID、运行 ID 和最近运行状态，不保存排名、个人事实或原文。刷新后可查询已知运行；`404 agent_run_not_found` 明确提示运行可能因重启或中断而不可查询，并允许重新发起。来源、自查与候选始终从各自的持久化读取接口恢复，运行 ID 不作为业务结果恢复的前提。

超时、网络错误或无法校验的响应保持结果未知；先提供刷新已保存结果及查看候选入口。用户主动再次发起前需确认原请求可能仍在执行，新请求采用新的操作 UUID；不自动重试。离开页面取消浏览器等待，不表示后台运行已停止。服务端返回授权、来源或模型错误时展示失败反馈，不自行绕过授权检查。

补录后的重新自查沿用 Agent 运行入口，需在个人事实保存成功、字段约定及最新事实读取方式明确后接入；当前公开来源分析不会提交未保存的排名。候选决定仍使用候选计划模块，关键拦截规则由后端统一。

## 页面状态与协作边界

首次读取显示加载态；读取失败提供重试；空列表说明关联条件。网络中断、超时或服务临时不可用时，刷新保留上次资料并标明读取时间；身份、权限、事项不存在或响应校验未通过时清除已展示资料。切换事项立即清除旧事项数据并取消未完成请求，旧请求返回不会覆盖当前事项。

`SourceConditionsPage.vue` 已通过 `workspaceIntegrations.modules.sources` 注册到 `/matters/:matterId/sources`，接收 `matterId`、只读的 `matter`，共用应用 Pinia、Vue Router 和 Element Plus。来源登记成功后发送 `changed`，工作区重新读取事项。要求列表接收快照与可用出处集合，通过事件请求切换出处。业务样式限定在 `.business-module` 内，沿用工作区的品牌色、字体及卡片样式。

后续联调需要后端业务服务、数据库迁移和真实事项数据。公开来源分析及状态查询已接入约定接口；自查完整保存、刷新恢复及重启后的读取需待后端链路接齐后验收。排名补录已完成输入和本地校验，排名保存与补录后的重新自查尚未接通。

## QA 入口与定位约定

真实测试服务接入方式见前端 README。来源页入口为 `/matters/{matter_id}/sources`，候选页为 `/matters/{matter_id}/plan`；从真实创建接口返回的事项 ID 进入。现有 `npm run test:matters:live` 仅检查事项创建、列表、详情和刷新，来源及候选完整链路仍需独立执行。

| 目标           | 定位方式                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 来源页及刷新   | `getByTestId('sources-page')`、`getByTestId('sources-refresh')`                                                                     |
| 读取表单       | `getByTestId('source-import')`，输入项 `#source-url`、`#source-publisher`、`#source-scope`                                          |
| 读取操作及结果 | `getByTestId('source-read-submit')`、`getByTestId('source-read-result')`                                                            |
| 来源及版本     | `getByTestId('source-card')` 按 `data-source-id` 区分；`#snapshot-version` 切换版本                                                 |
| 要求及自查     | `getByTestId('requirements')` 的 `data-snapshot-id`；`requirement-card` 的 `data-requirement-id`；`self-check` 的 `data-conclusion` |
| 排名输入       | `#ranking-rankPosition`、`#ranking-totalStudents`、`#ranking-confirmed`                                                             |

验收时先读取真实来源，核对返回的来源及快照 ID；未生成要求时检查“已读取，待分析”。要求与自查结果保存后，刷新及重新进入事项，按相同 ID 对照四态、原因、缺失信息、缺口和原文出处。重启后端后重复读取，确认结果来自持久化数据。后端尚未完成来源立即关联、自查保存及读取时，这些恢复用例保持待测。

分析入口与状态查询分别使用 `analysis-start`、`analysis-status-refresh`；已保存结果重读使用 `analysis-results-refresh`。反馈区 `analysis-result` 包含 `data-run-id`、`data-run-status` 和 `data-source-id`，错误区为 `analysis-error`。未完成运行的验收应在发起后刷新或重启服务，查询已知运行，核对找不到时的明确提示及重新发起操作；不恢复原运行。真实中断及重新发起仍待可用后端联调。


单元检查覆盖外链安全、事项标识输入、未知机器状态、时间精度、自查四态展示、缺失结果、自查字段校验、排名非法输入和比例边界。真实来源展示、版本切换、自查结果读取与刷新、事项隔离需在真实后端与数据库启动后联调验收。
