# OfferPilot 个人事项前端

Vue 3 + TypeScript + Vite 应用，提供个人事项列表、新建表单、事项工作区、概览及来源/条件、候选计划、正式任务的统一入口。界面采用中文、紫色主题与左侧导航。

## 安装与运行

需要 Node.js 24 LTS 和 npm 11。进入仓库的 `frontend/` 目录后执行：

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

打开终端输出的 `http://127.0.0.1:5173`。`.env.local` 仅保存可公开的前端配置。模型密钥和身份凭据由后端管理。默认配置不连接业务服务，页面明确呈现未接通状态；可以导航、填写及校验表单。服务未接入时不会产生事项数据。

## 检查与构建

```powershell
npm run lint
npm run format:check
npm run type-check
npm run test:unit
npm run build
npm run preview
```

纯逻辑测试检查表单、路由和状态语义。浏览器检查使用实际运行的前端，不拦截请求、不替换业务响应：

```powershell
npx playwright install chromium
npm run test:e2e
```

Windows 已安装 Edge 时也可使用现有浏览器：`$env:PLAYWRIGHT_CHANNEL='msedge'`，然后执行 `npm run test:e2e`。

默认浏览器检查覆盖未接通状态下的导航、深链接、表单校验和反馈。连接 Alpha 测试服务后，通过下方独立命令复测真实创建和重读。

## 本地真实事项联调

事项 API 对应业务 PR #41；来源、排名、授权和重新自查联调使用 `ad77166` 及截至 0015 的数据库迁移。准备可启动的 Alpha API、独立 PostgreSQL 测试库和演示身份后，在 `.env.local` 配置如下，并重启开发服务器。

```dotenv
VITE_LOCAL_DEMO_MATTERS=1
API_PROXY_TARGET=http://127.0.0.1:8000
```

开发服务器同源转发 `/api`。事项界面使用 `/api/v1/matters` 的真实请求，按服务端返回的 UUID 跳转；概览和浏览器刷新都会重读同一事项。超时或响应无法核验时保留表单并提示先核对列表。此模式使用后端配置的固定演示身份，只有显式启用的 Vite 开发服务会激活。生产构建沿用团队统一请求层的接入约定。

在可写的隔离测试库上执行浏览器验收。命令每次创建一条 `Alpha 联调` 测试事项，保留在测试库中供复查。

```powershell
$env:API_PROXY_TARGET = 'http://127.0.0.1:8000'
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm run test:matters:live
```

已有 Playwright Chromium 时可省略 `PLAYWRIGHT_CHANNEL`。此命令另启动 5174 端口的开发服务器，核对 POST `201`、列表 `200` 含同一 UUID、从列表点入详情 `200`，以及刷新再次返回相同 UUID。测试结果与失败追踪保存在 `test-results/matters-live/`。

## 团队共享客户端接入

1. 事项、来源和候选计划共用 `src/shared/http.ts` 的 Axios 客户端。它满足 `src/modules/matters/api.ts` 中 `SharedHttpClient`，返回 `{ data: T }`，支持读取取消与超时。各业务模块保留自己的响应校验和错误展示。
2. 共享客户端的 `baseURL` 使用后端真实前缀 `/api/v1`；事项适配器请求相对路径 `/matters`，不得重复拼接前缀。
3. `src/app/integrations.ts` 已通过 `createMattersApi(http)` 接入事项适配器。默认不连接业务服务；开发联调按上述环境配置启用。生产服务连接由集成负责人配置。
4. 若接入 #41 的固定演示身份，同时提供 `identity: { mode: 'single-user-local', label: '单用户本地演示' }`，明确展示运行限制。客户端不得自行伪造登录状态。实际身份变更后应重新挂载应用并清理业务状态。
5. `.env.local` 中的 `API_PROXY_TARGET` 指向实际启动的后端；只在显式指定时启用开发代理。生产部署须提供 `/api` 的同源反向代理，以及 Vue Router 的 SPA 深链接回退。`npm run preview` 只检查静态构建，不承担业务服务转发。
6. 来源与条件、候选计划审阅已分别通过 `workspaceIntegrations.modules.sources`、`plan` 注册，由张锦昊维护。各组件接收 `matterId` 和只读用途的 `matter`，写入完成后触发 `changed`，父工作区重读事项。同事项重读保持业务组件，事项变化时清除旧上下文。陈常群负责的整体任务页继续使用 `tasks` 注册点。

接口和模块约定见[工作区集成约定](workspace-integration.md)。

## 交互约束

- 事项 ID 只采用后端返回的 UUID，概览重新读取服务端内容。非法参数与未知路由提供恢复入口。
- 读取时取消旧请求，并使用请求序号阻止旧响应覆盖；切换事项清除前一事项内容。
- 未连接、加载、真实空结果、读取失败分别展示。未读取不表示没有事项。
- 表单仅在页面内保留；离开未保存表单会提示。保存中禁止重复提交和路由离开。
- 创建请求网络异常、服务异常或响应无法核验时，写入结果视为未知。当前创建契约没有幂等键或操作查询，需先到列表核对，禁止自动重试或声称未写入。
- 来源模块支持公开 HTML 通知读取、关联来源与历史快照、原文和要求引用展示；候选模块支持计划审阅、确认/拒绝、稳定操作标识重试及确认后的任务重读。
- 来源要求返回 `self_check` 时，逐条展示四态自查结论、判断原因、缺失信息与缺口出处；字段未返回时提示尚无可读取结果。后端 #41 提供保存和按事项读取，联调数据库需应用截至 0015 的迁移后验证真实刷新及重启恢复。
- 来源页可对已读取或选择的公开来源发起 Agent 分析、查询运行状态，并刷新已保存的来源与候选结果。等待补充、失败、运行找不到和结果未知分别提示；分析请求不创建正式任务。按事项保存到当前标签页的运行标识仅辅助查询，业务结果始终由来源和候选接口重新读取。
- 当前事项提供排名补录、正整数及范围校验、本人真实性确认、事项级保存与读取，以及保存后重新自查。保存后重读核对版本，再由 Agent 读取后端的当前事项事实；未保存输入不参与自查，失败保留输入。缺少来源或尚无可用授权时可先保存，满足条件后仅重新自查。本地比例展示不判断资格。整体任务页保留注册点，任务状态更新不在本模块中实现。
- 分析区读取并展示当前用户的统一模型传输披露信息，用户主动确认后授予；撤回后重读并停用旧标识。分析前再次读取授权，由后端查询当前用户的统一授权；授权结果不确定时停止新分析并提示核对。
