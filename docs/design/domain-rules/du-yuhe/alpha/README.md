# OfferPilot Alpha 推免规则与验收样例

杜玉鹤 · 领域规则 · v1.0.0 · 2026年11月18日

每条样例都给出条款出处、适用对象和证据不足时的预期结果。样例取自两所学校三个学院发布的2027年推免通知。通知发布于2026年，所选批次的报名或材料提交窗口均已结束。以下个人事实均为验收用的合成输入。正式资格及录取结果以校方认定为准。

**交付结果**　11条局部规则、38个领域用例、1条可追溯的候选任务和6组用户决定样例均已完成本地核对。项目 Agent 开发分支的13项判定实测中，9项符合预期，4项有差异。详见[验证记录](验证记录.md)。

## 一次演示怎么走

1. 选择福大数统学院2027届校内推荐事项，回放时间设为2026年9月9日。A04给出的个人事实只有“纸质成绩单已备好”。
2. 打开第（5）项。清单第3目还要求对应电子版，因此本项显示**待补充信息**，具体缺口是按规定命名的成绩单PDF。申请材料提交界限为9月10日15:00前。[学院原文](https://math.fzu.edu.cn/info/1171/10393.htm)
3. 打开候选任务T-01“备齐与纸质成绩单对应的电子版，供本人提交”。在任务依据中可分别回看成绩单要求和提交时限。9月9日是个人建议准备日。该任务只补缺少的电子件。
4. 对照P01至P05。只看或拒绝候选时，正式任务预期为0条。按有效版本确认后预期为1条，重试同一操作仍为1条。依据已换版时需重新生成。P06演示11月回看已结束批次。各路径的增量、前提和预期均在[候选计划样例](plan.json)内。

## 规则与预期结果

“匹配／不匹配／范围不明”说明该条款是否适用。只有适用或范围待核对的条目才显示个人自查状态。四种状态为“按现有信息符合”“按现有信息不符合”“待补充信息”“待用户核对”。前两种只描述被核对的那一项。个人材料缺失时写明需补什么，官方证据或范围有疑点时标出待核对的位置。

| 规则 | 分阶段适用的要求 | 验收入口 |
| --- | --- | --- |
| GR-01 · S4 | 学院第（3）项另引校级文件。即使成绩单已齐，现有证据也不足以判断整套推荐资格。 | A01 |
| GR-02 · S4 | 本届、本院自愿申请推荐者须在2026-09-10 15:00前交材料。14:59满足该时限，15:00到点按原文“前”处理。 | A02–03、A08–09、A38 |
| GR-03 · S4 | 教务自助打印的一份成绩单及相应电子版分别核对。放弃推荐者另有承诺书要求。 | A04–07、A35、A37 |
| GR-04 · S5 | 校内预报名、教育部系统正式报名分别留本人记录。专业目录缺失时仍可核对正文里的报名步骤。 | A10–11 |

## 文件和复核

| 文件 | 查什么 |
| --- | --- |
| [sources.json](sources.json) | 按 `source_id` 查来源及版本。附一次实际读取失败、恢复情况，以及只缺目录附件的输入样例。 |
| [rules.json](rules.json) | 按 `requirement_id` 查条件、比较符、限定词、`DYH-R` 编号和证据。适用范围由来源的 `scope` 与本条 `scope` 共同确定。 |
| [cases.json](cases.json) | 按A编号查事项、已确认事实、证据可用性和预期结果。范围不匹配时 `status` 为空。 |
| [plan.json](plan.json) | 从T-01反查要求、来源版本、原文位置和触发缺口，再查看P01至P06的决定路径。 |
| [验证记录.md](验证记录.md) | 公开来源实测、开发分支输出、复现命令和待联调内容。 |

在解压后的本目录运行以下命令。第一条使用本地文件核对规则、用例和候选引用，第二条从三家学院官网重新读取正文及附件。两条命令均只依赖Python标准库。项目使用Python 3.13。

```text
python -B verify.py
python -B check_sources.py
```

复核 Agent 分支时，使用该分支的后端环境运行 `compare_agent.py`，传入项目根目录。存在差异时脚本返回非零状态，并逐项保留实际输出。可用同一批输入复测修复后的版本。[运行环境及结果](验证记录.md)
