# Alpha 推免验收判定与复现

S4 是福州大学数学与统计学院的2027届校内推荐工作方案。演示从原文第（5）项提取交材料的期限和成绩单要求。候选任务 T-01 同时引用这两处证据，保留原文期限与个人建议准备日。[出处及演示范围](README.md)

## 候选计划决定

| 用例 | 触发条件 | 候选状态 | 正式任务 |
| --- | --- | --- | --- |
| P01 | 查看新候选 | 待确认 | 0条 |
| P02 | 拒绝待确认候选 | 已拒绝 | 0条 |
| P03 | 当前来源与候选引用一致，首次确认 | 已确认 | 新增1条 |
| P04 | 按原操作编号重试确认 | 已确认 | 保留第一次写入的同一条任务 |
| P05 | 给同一来源登记新快照，仍用原候选发起确认 | 需重新生成 | 新增0条，保留候选原引用 |
| P06 | 在期限结束后查看历史批次 | 仅供历史参考 | 0条 |

P05 与 P03 使用同一种确认操作。P05 的输入先替换当前来源版本，候选仍引用旧版本。验收同时检查状态、`basis_changed` 错误和任务数。业务接口接受同一来源的新快照后，旧候选的确认应返回 HTTP 409，并持久化为 `expired`，不产生确认决定或正式任务。[决定输入与预期](plan.json)

## 规则及来源

离线校验匹配用途、院校、年度、届别、阶段及申请路径。校内预报名后再正式报名的样例要求两段个人记录，任一缺失会标出对应的字段。专业目录缺失时，仅依赖目录的判断保留缺口。历史条件用于回放，正式资格以院校认定为准。[规则与出处](rules.json) · [用例数据](cases.json)

来源校验比对官网正文和附件内列明的条款位置。每个来源有15秒的下载总预算及最多3次尝试，临时请求失败按短间隔重试。固定版本的招生专业目录换版时，需要回到原表对照学位类型、代码和专业名称。[公共来源索引](sources.json)

```text
python -B verify.py
python -B check_sources.py
```

## 与实现对照

Agent 对照输入规则类型、参数、原文定位和条款级附件依赖，比较判定状态、期限与适用的个人信息缺口。使用已支持这些字段的 Agent 分支运行。

```text
uv run --project "<Agent检出目录>/backend" --locked --no-dev python -B compare_agent.py "<Agent检出目录>"
```

业务 API 对照使用独立 PostgreSQL 测试库。准备已应用 Alpha 迁移、可登录演示账户、可登记测试来源和快照的后端测试连接，将其配置至 `OFFERPILOT_TEST_DATABASE_URL`。在演示工作区准备三个带已发布模板版本的空白推免事项。脚本按数据库的草稿到待确认状态准备候选，随后通过候选决定 API 完成 P01 至 P05，并重读候选及其事项下的正式任务。每次用新测试库回放，以保证开始时官网样例对应的快照为当前版本。新快照中的标记仅用于模拟内容变化。

```text
uv run --project "<业务API检出目录>/backend" --locked python -B compare_backend.py "<业务API检出目录>" "<事项ID1>" "<事项ID2>" "<事项ID3>"
```
