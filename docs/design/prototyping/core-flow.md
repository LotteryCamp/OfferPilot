# 核心流程原型与状态说明

Issue #26 · 设计规格。页面参考来自现有 Page 2 点击原型。下文规定界面应展示的内容和行为，功能实现与验收进度以相应实现 PR 为准。

依据 [核心流程范围、数据契约与验收基线](../../development/core-flow-contract.md)，本流程仅覆盖单个个人推免事项、一份约定的公开 HTML 来源、候选计划决定和个人任务结果。

## 必显信息的位置

| 位置 | 展示内容 |
| --- | --- |
| 工作区标题下方 | 事项适用年度、对象或项目，以及适用的院校、学院、专业、批次或路径。未知维度显示「待核对」。工作区概览保留缺口摘要及「来源与条件」入口。 |
| 来源卡片与要求列表 | 来源卡片展示标题、发布机构、原文链接、获取时间、快照版本、来源可用性和自动检查状态。要求行展示提取值、义务性质、适用范围和原文段落定位。缺口区指出缺少的证据、受影响的要求及是否阻止确认。自动检查通过与提取完成均用机器处理状态表述。 |
| 候选计划审阅区 | 页首显示版本、状态和适用范围。每项展示标题、义务性质、依赖、所需完成证据、来源快照、原文定位与短引文。官方截止日期或时刻与建议准备日分栏；原文只给日期时仅显示日期。未解决的缺口紧邻相关计划项展示，阻断原因同时出现在确认按钮附近。 |
| 任务列表与依据详情 | 任务卡片展示状态、官方期限、建议准备日和前置依赖。依据详情继承原计划项的出处与适用范围，并保留与该任务有关的待核对提示。 |

## 等待、失败与决定反馈

- 来源读取中显示「正在读取来源」。读取失败显示原因与「重试读取」，保留可用的既有依据。来源存在冲突、范围未知或证据缺失时显示「待核对」及对应缺口。
- 首次提交生成请求时使用稳定的幂等键，同一次生成的重试复用该键。服务端按事项协调并发生成，同一事项同一时刻只允许一个生成请求执行或一个候选版本处于待确认；其他标签页复用进行中的请求或返回已保存的待确认版本。需要替换候选时，旧版本须先退出待确认状态。
- 生成中显示「正在生成候选计划」。响应丢失时用原键查询或重试并恢复已保存的候选版本；已生成但读取失败时提供「重试读取计划」。模型超时或输出无效且服务端确认生成失败时，显示失败原因与「重试生成」。成功读取已保存的候选计划后才显示审阅入口。
- 提交确认或拒绝期间禁用两个决定按钮。响应丢失时提示「结果待核对」，沿用本次幂等键重试并读取持久化结果。并发冲突时刷新到服务端返回的候选状态；界面以服务端决定和任务结果为准。
- 依据变更导致候选过期时显示「已过期」并提供「重新生成候选计划」。来源不可用、存在关键缺口或官方期限已过时显示具体原因并阻止确认。重新生成的版本须重新审阅。
- 任务读取中显示加载状态，读取失败提供「重试加载」。仅在读取成功且返回空列表时显示「暂无任务」。

## 原型走查路径

1. 创建推免事项 → 进入工作区 → 打开来源结果 → 查看要求的出处、适用范围和缺口 → 打开待确认候选计划。此时对应任务尚未创建。
2. 从待确认计划点击「确认并创建任务」 → 看到「已确认」 → 点击「查看任务」 → 对照计划项核对任务、期限和来源。该路径要求依据有效且官方期限尚未届满。
3. 从另一份待确认计划点击「拒绝」 → 看到「已拒绝」及「本计划未创建任务」 → 返回工作区核对任务列表。重新打开该版本时仍显示原决定。

按当前时间走查时，基线中的福州大学数学与统计学院通知用于核对「批次已结束」提示和确认拦截。正常确认路径的实时验证使用系统当前时间及仍在有效期内、适用范围明确的真实公开通知；可用来源须符合支持的公开 HTML 范围。基线另行规定的固定时点历史回放用于验证该样例在当时的提取与状态，按实际验证方式记录结果。
