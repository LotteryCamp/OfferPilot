# Beta 工作区 11 月 28 日实现走查

对照 [Figma Page 3 交付区](https://www.figma.com/design/feczCbKUHrybftac7eB7qW/OfferPilot?node-id=27-332) 和 [#72 的设计验收要求](https://github.com/LotteryCamp/OfferPilot/issues/72)，检查首屏、主次操作、留白、重复内容、窄屏和异常恢复。差异供 [#76](https://github.com/LotteryCamp/OfferPilot/issues/76) 收口。

## 复测范围与结果

本地使用组合版本 `test/beta-auth-current@7ed5601`、Edge、独立 PostgreSQL 16 和真实 API。前端候选与任务的有数据状态另核对了 [PR #85 的实际页面截图和组合联调记录](https://github.com/LotteryCamp/OfferPilot/pull/85)。

| 检查 | 结果 |
| --- | --- |
| 工作台及工作区导航 | 登录后可进入事项工作台，空工作台有创建入口。事项概览、无来源、无候选和无任务状态在 1440、1100、700、390 px 均无页面级横向溢出。 |
| 来源与错误恢复 | 读取福州大学材料科学与工程学院公开通知返回 `201`，页面读回来源。限速时刷新按钮显示加载状态。断网刷新时显示「读取未完成」和重新读取入口，恢复网络后可读回。服务端会话失效后刷新来源，跳转登录并显示会话失效提示。 |
| 排名与模型传输同意 | 未授权时保存测试排名 18/120 返回 `200`，页面显示已保存的 v1，禁用「仅重新自查」。直接调用正式 Agent 入口返回 `422 model_transfer_consent_required`。 |
| 候选与任务 | 本轮重走了真实空状态。#85 截图中，候选可展开原文依据，过期后可返回来源重新分析；任务展示官方期限、建议准备日和依赖。#85 另有刷新后的决定与任务读回证据。 |

## 给前端的差异记录

| 优先级 | 页面与触发条件 | 实际表现 | 预期表现 |
| --- | --- | --- | --- |
| 高 | 来源与条件，在 390 × 844 px 从工作区进入已读来源页 | 完整页面的业务标题从 y=558 px 开始，排名按钮从 y=807 px 开始，底边在 y=852 px。全局导航、账户栏、事项标题和两组导航挤占首屏。「新建工作区」比当前事项动作更早出现且使用主按钮样式。 | 窄屏压缩工作区导航与页头，将当前快照、关键缺口和当前事项主操作完整放进首屏。无来源时优先给出读取通知入口。 |
| 高 | 来源与自查，先保留补录前的历史自查，之后保存本人排名 | #85 的来源截图同时显示「本人排名已保存 v1」和历史结果「当前事项尚未保存本人排名」。历史版本标识可见，但结果与当前事实之间的关系需要用户推断。 | 在历史自查卡片就近标明其使用补录前的事实。保留已保存排名状态，提示授权有效后重新自查，重查前继续保留已读历史证据。 |
| 中 | 排名补录，核对复选框后点「保存排名」，等待 v1 读回 | 保存成功后复选框复位，同时立即出现红字「请确认排名信息由本人核对且真实」。同一表单同时展示保存成功和确认错误。 | 保存成功后清除本次字段错误。用户编辑并再次检查或提交时，再按新的输入显示确认校验。 |
| 中 | 排名补录，已读取来源但未授权，保存测试排名 | 保存结果和表单底部两次重复授权原因，禁用的「仅重新自查」旁没有直达授权区的入口。「保存排名」「检查输入」「仅重新自查」「返回来源与条件」纵向占四行。 | 保存结果旁集中说明「排名已保存，尚未重新自查」，提供跳转到授权披露的入口。检查输入反馈靠近字段，保留清晰的返回动作，授权有效后恢复重试。 |
| 中 | 候选审阅，选择本人排名依据已变化的版本 | #85 桌面截图中，版本摘要、决定区和核对来源区重复强调核对与返回来源。「前往计划决定」位于摘要主路径，依据变化时真正可继续的「返回来源与条件重新分析」排在其后。 | 将阻断原因和受影响事实放在摘要，将返回来源重新分析作为该状态的首要入口。决定区保留禁用原因和按当前状态可用的拒绝动作，来源证据继续贴近对应条目。 |
| 中 | 阶段与任务，打开已确认计划产生的任务列表 | #85 的 390 px 截图先显示通用状态计数和来源链接，首屏缺少当前计划已确认及本次写入结果。桌面截图每项重复显示「查看已确认计划」，条目较长时右栏摘要下方留白明显。 | 首屏优先展示已读回的计划版本、确认结果和本次新增任务，再进入列表。共享计划入口集中在页级摘要，逐项保留期限、依赖与对应依据。 |

## 联合验收待补项

- 真实模型环境中，从新版排名重查连续完成候选审阅和任务读回。本地本轮验证到授权拦截、排名保存及页面恢复，候选与任务有数据状态使用 #85 的既有证据。
- P0-06 在 `main@29cd0b6` 已验证排名键对齐。#73 的真实模型复测仍发现两条自查把缺失的学分和补考／重修事实判为符合，且与全局缺口不一致。该场景记录为未通过，待后端修复后在同一通知和同一版本上复测页面结论、原因、剩余缺口和出处。[#73 联调结论](https://github.com/LotteryCamp/OfferPilot/issues/73#issuecomment-7241391660)
